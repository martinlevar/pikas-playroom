### Login y Usuario

La autenticacion usa Firebase Identity Toolkit mediante REST API.

La sesion se guarda en:

```text
localStorage: arcade-night-scoreboard-v1-auth
```

El usuario permanece logueado y se refresca el token cuando corresponde.

Desde el perfil el usuario puede:

- Ver sus estadisticas.
- Subir foto haciendo click en el avatar.
- Crear tableros.
- Ver sus tableros creados.
- Jugar, ver o eliminar tableros.
- Agregar administradores / editores invitados por email.

### Tableros

Cada tablero vive en Firebase bajo:

```text
rankings/{rankingId}
```

Campos importantes:

- `name`
- `slug`
- `visibility`: `public` o `private`
- `ownerUid`
- `editors`
- `invitedEditors`
- `coverImage`
- `state`
- `history`
- `betKeeper`
- `challengeScores`

Tableros publicos aparecen en el home. Tableros privados se comparten por link.

### Pikasnoid

Pikasnoid empezo como desafio arcade y evoluciono a un juego futbolero tipo arcade.

Estado actual:

- Canvas vertical.
- Control tactil pensado para celular.
- Arquero controlado por el usuario.
- Pelota blanca principal para hacer goles.
- Pelotas amarillas de despeje a partir de niveles avanzados.
- Rivales formados con comportamiento por pantalla.
- Jugadores rivales desaparecen al recibir impactos.
- Despues de varios golpes, jugadores pueden explotar y no volver.
- Partidos por tiempo.
- Sistema de puntos total.
- Bonus especial de penales/despejes despues del nivel 3.
- Modal/overlay diferenciado para victoria, derrota y bonus.
- Guardado de puntaje solo si el usuario esta logueado.
- El puntaje solo se actualiza si supera el mejor puntaje anterior.
- Ranking oficial por puntos totales.

Regla actual del ranking:

- El numero 1 del ranking es el campeon hasta ser destronado.

### BetKeeper

BetKeeper esta implementado como capa de reglas/acuerdo dentro de cada tablero, no como pagos reales todavia.

Estado actual:

- El creador puede habilitar BetKeeper al crear tablero.
- Si no se habilita, no ensucia el formulario.
- BetKeeper tiene modal propio.
- Se configuran valor de entrada, moneda, criterio ganador y reparto.
- "Mayor puntaje Pikasnoid" fue quitado como criterio.
- Si se elige criterio manual, aparece campo para completar el criterio.
- Reglas del juego y reglas de pago se abren en modales separados.
- Reglas de pago explican:
  1. Participan.
  2. Confirman el pago.
  3. Juegan.
  4. Todos dan OK al ganador.
  5. Premio liberado.
- En el home, los tableros con BetKeeper muestran indicador y boton para ver reglas.

Mercado Pago todavia no esta integrado.

## Firebase

Configuracion actual en:

```text
config.js
```

Incluye:

- `firebaseDatabaseUrl`
- `firebaseWebApiKey`
- `activeRankingId`
- `roomId`

Reglas en:

```text
firebase.rules.json
```

Reglas importantes:

- `rankings` tiene lectura publica.
- Escritura de tableros permitida al owner o editors.
- Owner puede crear/eliminar su tablero.
- Editores invitados se guardan bajo `invitedEditors`.
- `challengeScores` tiene lectura publica.
- Cada usuario autenticado solo puede escribir su propio score en `challengeScores/{challengeId}/{uid}`.
- `users/{uid}` solo puede leer/escribir el usuario autenticado correspondiente.

## Notas de Producto

El tono visual buscado es arcade 80s, futbolero, con energia de noche de amigos. La app no debe sentirse como landing generica sino como una herramienta viva para crear, jugar y mirar torneos.

Para Pikasnoid, el modulo del home debe funcionar como marketing: logo, portada fuerte, sensacion de cartucho/juego clasico y ranking visible.

Para tableros, la prioridad es claridad:

- Home: mirar tableros publicos y entrar/login.
- Perfil: crear y administrar.
- Mesa: jugar/cargar puntos.
- Viewer: mirar sin tocar.
